0. WHAT YOU ARE BUILDING (30-SECOND PICTURE)
================================================================================

PROBLEM:
  A camera measures each dry bean (size, shape, roundness, etc.).
  You want a computer to automatically label which of 7 bean types it is.

SOLUTION (this repo):
  1) Clean and enrich the data          → data_alignment.py
  2) Train & compare 6 ML algorithms    → benchmark_models.py
  3) Pick the best model + tune it      → GridSearchCV inside benchmark
  4) Measure quality (accuracy, F1, CM) → reports/*.json
  5) Visualize results                  → visualize_results.py
  6) Explain WHY the model decides      → explain_model.py (SHAP)
  7) Serve predictions over HTTP        → app.py (Flask API)
  8) Automate everything in CI/CD       → Docker + Jenkins

DATA:
  - Source: Data_sets/Dry_Beans_Dataset.csv  (13,611 rows, 7 classes)
  - After alignment: Data_sets/train_dataset.csv (+ 5 engineered features)

BEST MODEL (from your last successful run):
  - Name: svm_tuned
  - Holdout accuracy: ~93.65%
  - Macro F1: ~0.946

STEP 4.2 — Model benchmark + tuning (15–45 minutes on laptop)

  PHASE 2: GridSearchCV on TOP 3 models only (faster than tuning all 6)

5. WHAT EACH FILE / OUTPUT MEANS
================================================================================

FILE                              | WHAT IT IS
----------------------------------|--------------------------------------------
Dry_Beans_Dataset.csv             | Raw UCI dataset (13,611 beans, 7 classes)
train_dataset.csv                 | Cleaned + 5 engineered features + encoding
benchmark_config.yaml             | Single source of truth: paths, CV, models
benchmark_results.csv             | All models: default + _tuned rows
best_model.joblib                 | Serialized winning pipeline (load with joblib)
model_metadata.json               | Feature names, class names, tuned params
confusion_matrix.json             | Which classes get confused with which
classification_report.json        | Per-class precision/recall/F1
performance_chart.png             | Main dashboard for README / presentations
learning_curves.png               | Train vs validation accuracy vs data size
shap_importance.png               | Global feature importance

KEY METRICS (memorize for interviews):
  - Accuracy     = % correct overall
  - Macro F1     = average F1 across classes (good for balanced multi-class)
  - Holdout      = accuracy on 20% test set never seen during training
  - CV (5-fold)  = average accuracy across 5 train/val splits on training data
  - Confusion matrix = rows=actual, cols=predicted

7. RUN WITH DOCKER (PRODUCTION-STYLE)
================================================================================

PREREQUISITE: Docker Desktop must be RUNNING (whale icon in system tray).

From project root in PowerShell:

  STEP 7.1 — Build image
  docker build -t bean-classification:local .

  STEP 7.2 — Data alignment + copy CSV to host
  docker run --rm -v ${PWD}:/workspace -v ${PWD}/models:/app/models -v ${PWD}/reports:/app/reports -w /app bean-classification:local sh -c "python Scripts/data_alignment.py && mkdir -p /workspace/Data_sets && cp /app/Data_sets/train_dataset.csv /workspace/Data_sets/"

  STEP 7.3 — Benchmark
  docker run --rm -v ${PWD}/Data_sets:/app/Data_sets -v ${PWD}/models:/app/models -v ${PWD}/reports:/app/reports -w /app bean-classification:local sh -c "python Scripts/benchmark_models.py"

  STEP 7.4 — Visualize
  docker run --rm -v ${PWD}:/workspace -v ${PWD}/Data_sets:/app/Data_sets -v ${PWD}/reports:/app/reports -w /app bean-classification:local sh -c "python Scripts/visualize_results.py && cp /app/performance_chart.png /workspace/"

WHY DOCKER (FAANG):
  Same environment everywhere = "works on my machine" problem solved.
  Jenkins runs the same container your Dockerfile defines.

10. HOW TO TALK ABOUT THIS PROJECT IN INTERVIEWS (30-SECOND PITCH)
================================================================================

"Built an end-to-end ML pipeline for 7-class dry bean classification on
13k morphological samples. Engineered domain features, benchmarked six
classifiers with stratified cross-validation, tuned the top performers
with GridSearchCV, and deployed the best SVM via joblib with a Flask
inference API. Added SHAP explainability, learning curves, and a
Dockerized Jenkins CI/CD pipeline for reproducible training and artifact
archival. Achieved ~94% holdout accuracy with per-class confusion
matrix analysis."

FOLLOW-UP QUESTIONS YOU SHOULD ANSWER:
  Q: Why stratified split?
  A: Keeps same % of each bean class in train and test.

  Q: Why macro F1?
  A: Treats all 7 classes equally; good when no single class dominates.

  Q: Why SVM with RBF?
  A: Non-linear boundaries in high-dimensional shape features; tuned C/gamma.

  Q: How do you know you're not overfitting?
  A: Compare CV vs holdout; learning curves; confusion matrix per class.

  Q: What would you improve next?
  A: Class imbalance handling, PCA for correlated features, MLflow tracking,
     Kubernetes deployment, integration tests on API, faster CI with caching.

11. TROUBLESHOOTING
================================================================================

PROBLEM: python is 3.7 / packages fail to install
FIX:     Install Python 3.9+, use: py -3.9 -m venv .venv

PROBLEM: Benchmark runs forever with no output
FIX:     Use: python -u Scripts\benchmark_models.py
         Or set enable_tuning: false in config for a quick test

PROBLEM: joblib / n_jobs crash on Windows
FIX:     Already handled (n_jobs=1 on Windows). Use Python 3.9+ venv.

PROBLEM: Docker: "cannot find pipe dockerDesktopLinuxEngine"
FIX:     Start Docker Desktop and wait until it is fully running

PROBLEM: train_dataset.csv missing before benchmark
FIX:     Run data_alignment.py first

PROBLEM: app.py fails — model not found
FIX:     Run benchmark_models.py first

PROBLEM: SHAP warnings about feature names
FIX:     Safe to ignore if shap_importance.png was created

PROBLEM: predict API needs 21 features
FIX:     curl http://localhost:5000/info  → copy feature list from metadata
